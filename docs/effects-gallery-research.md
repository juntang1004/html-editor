# HTML Slide Studio 효과 갤러리 조사

조사일: 2026-11-19. 이 문서는 후속 구현을 위한 제안이며, 효과 실행이나 브라우저 시각 검증을 완료했다는 뜻은 아니다. 프로젝트 스킬 목록과 작업팀 운영 문서 4개를 확인했다. 본 조사에 직접 해당하는 프로젝트 스킬은 없었다.

## 방향

외부 사이트의 효과 분류와 조절 방식을 참고하고, 앱의 기본 효과는 자체 CSS·Web Animations API(WAAPI)·SVG로 구현한다. 라이브러리별 엔진을 모두 넣지 않는다. 아래 54개는 발표 적합성과 구현 난이도로 선정한 후보이며 사용량 순위가 아니다. 여러 카탈로그에 반복해서 나타나는 기본 패턴과 더 복잡한 확장 패턴을 구분했다. 실제 인기도 통계는 수집하지 않았으므로 UI에 ‘인기 1위’ 같은 문구를 붙이지 않는다.

## 구현 계약 제안

1. 효과마다 안정적인 effectId, 표시 이름, 대상 종류, 기본 시간, easing, 지원 옵션, reduced-motion 대체 방식, 출처 메모를 정의한다. 적용된 액션은 별도 actionId, 대상 elementId 목록, durationMs, delayMs, trigger, afterActionId를 가진다. 시간은 내부적으로 ms 하나로 관리하고 UI에서 s로 변환한다.
2. ‘0.2s를 2s로’는 기존 actionId의 durationMs를 200에서 2000으로 수정한다. 새 액션을 몰래 추가하거나 HTML 전체를 다시 작성하지 않는다. 대상이 여러 개면 선택 개체/선택 액션을 우선하며 결과 미리보기와 실행 취소를 제공한다.
3. ‘검정 화면→밝아짐→그래프 성장’은 22번 완료를 25번의 의존 조건으로 저장한다. 완료 Promise/이벤트로 다음 단계를 시작해 첫 액션 길이가 변경돼도 순서가 유지되게 한다. 일시정지·취소·페이지 재진입 시 대기 중인 단계도 정리한다.
4. 갤러리 카드, 실제 슬라이드, 전체 화면 발표가 같은 효과 등록부와 실행기를 쓴다. 카드용 축소 렌더러에 별도의 효과 코드를 만들지 않는다. 카드에는 재생·정지·시간·적용·원본 코드 보기를 제공하고 전체 카드를 동시에 재생하지 않는다.
5. 외부 CDN 없이 앱에 필요한 코드·폰트·아이콘을 로컬 번들한다. 갤러리는 네트워크를 끊어도 동작해야 한다. 외부 참고 링크는 사용자가 선택해서 열 때만 필요하다.
6. 편집기 선택 테두리와 ‘모든 개체 테두리’는 애니메이션 대상 DOM과 분리한 오버레이로 그린다. 배포 HTML과 PDF에 편집 테두리가 섞이지 않게 한다.

## 그래프·접근성·검증 기준

- 그래프 전체를 scale하지 않는다. 축, 눈금, 범례, 데이터 라벨은 고정하고 막대/선/점 등 데이터 마크에만 적용한다. 막대의 기준점은 데이터의 0 또는 실제 baseline이다. 음수 막대는 반대 방향으로 성장해야 한다.
- 이미 한 장의 이미지로 굳어진 그래프에는 개별 막대 성장 기능이 있다고 표시하지 않는다. SVG/DOM에서 데이터 마크를 구분할 수 있을 때 지원하고, 그 외에는 전체 이미지 reveal만 제공한다. 캔버스 차트는 해당 차트 엔진 어댑터가 있을 때만 세부 편집한다.
- 숫자 보간은 원래 값·소수점·단위·음수·천 단위 구분을 보존한다. 글자 분리는 한글 결합과 이모지를 깨지 않도록 grapheme 기준으로 처리하고 스크린리더용 원문을 유지한다.
- prefers-reduced-motion에서는 큰 이동·회전·스프링을 제거하고 즉시 최종 상태 또는 짧은 opacity 변화로 대체한다. OS 설정과 앱 설정 모두 적용하며, 순차 실행의 완료 조건이 중단되지 않아야 한다.
- 정지·재생·처음부터 재생과 키보드 조작을 지원한다. 갤러리 미리보기의 자동 재생은 제한하고 화면 밖 카드는 중단한다.
- PDF는 최종 상태를 사용한다. 등장 전 숨겨진 글자나 빈 그래프가 저장되지 않는지 검증한다. HTML 저장·재열기에서 actionId와 옵션이 보존되어야 한다.
- 핵심 회귀 검증: 200→2000ms 수정, 단일 액션 수정/실행 취소, 22→25 순서, 연속 재생·취소·페이지 재진입, reduced-motion 전환, 음수/쌓인 막대와 고정 축, 한국어 제목, 오프라인 실행, 최종 상태 PDF, 미리보기와 실제 화면 일치.

## 권장 개발 순서

먼저 공통 액션 스키마·수정/실행취소·완료 의존 관계를 만든다. 이후 기본 효과 1–15와 22·25–30을 연결하고 실제 슬라이드에서 검증한다. 나머지 기본 효과, 갤러리 검색/필터, 텍스트·SVG 확장, 53·54의 복합 프리셋 순으로 늘린다. 카탈로그 개수보다 기존 액션 시간 수정과 재현 가능한 순차 실행이 먼저 통과해야 한다.
